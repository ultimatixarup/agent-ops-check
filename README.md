# agent-ops-check

**Run an agent-ops review on your own computer with one command.** No SaaS, no account, no network calls.
Optional LLM review uses your own API key, and only if you ask for it.

```bash
npx github:ultimatixarup/agent-ops-check ./my-agent
```

Then open `agent-ops-report/index.html` in your browser.

Other ways in:
- A zipped agent: `npx github:ultimatixarup/agent-ops-check ./agent.zip` (extracted locally to a temp folder, deleted after; path-traversal entries are rejected)
- A local launch page: `npx github:ultimatixarup/agent-ops-check ui --open` serves a page on `127.0.0.1` where you type a folder/zip path or upload a zip, start the scan, and view the report

> Heuristic regex and static checks, **not a security audit**. It can miss problems and it can flag harmless code.
> Free, MIT-licensed personal project.

**White paper:** [docs/WHITEPAPER.md](docs/WHITEPAPER.md) ([PDF](docs/whitepaper.pdf)): the needs, design, checks, standards mapping, a worked example and the limits.

## Needs and checks

Each section states an unmet need with sourced figures, the checks that address it, and the details of each check. The check tables are generated from `rules/*.yaml` and `docs/checks-catalog.yaml` by `npm run docs`; a test fails if they drift.

### Personal data leaking into work channels

**The need.**

- A personal "CFO" agent posted a private monthly money report to a work Slack chat named "Exec-team". Its owner: "they're actually all using the same connections, even if they feel like different agents." (Business Insider, as-told-to essay by Shane Mac, October 9, 2026)
- In a VentureBeat Intelligence survey of 137 respondents (October 5, 2026), 62% of firms with agents in production let agents share credentials; only 38% give each agent its own identity.

**Where:** Tab 1: Personal-to-work crossover.

**Checks that address it:** `crossover.source_to_sink`, `crossover.shared_credential`, `crossover.env_committed`, `crossover.slack_webhook`, `crossover.teams_webhook`, `crossover.discord_webhook`, `crossover.slack_channel_id`, `crossover.secret.*`, `crossover.pii.*`

| Rule ID | Severity | What it looks for | Example finding | How to fix |
|---|---|---|---|---|
| `crossover.source_to_sink` | high | Per agent folder: any personal source (personal_sources in rules/crossover.yaml) AND any work sink (work_sinks) in non-doc files. | Agent 'finance-cfo' can read personal sources (gmail, tax_paths) and write to work sinks (slack). | Split personal and work agents, scope tokens read-only, allowlist output channels. |
| `crossover.shared_credential` | high | The same credential env-var name (…TOKEN/KEY/SECRET…) used by more than one agent folder, including MCP config env blocks. | Credential SLACK_BOT_TOKEN is used by 2 agents: finance-cfo, work-assistant. | Give each agent its own scoped token. |
| `crossover.env_committed` | high | A .env file inside the scanned folder (its contents are never read). | .env file present in the agent folder. | Remove it from the repo and rotate what it held. |
| `crossover.slack_webhook` | high | Hardcoded Slack webhook URL. Anyone with the file can post to that channel. Pattern: `https://hooks\.slack\.com/services/[A-Z0-9]+/[A-Z0-9]+/[A-Za-z0-9]+` | Hardcoded Slack webhook URL (masked). | Move it to a secret store; rotate it. |
| `crossover.teams_webhook` | high | Hardcoded Microsoft Teams webhook URL. Pattern: `https://[a-z0-9.-]*webhook\.office\.com/[^\s"']+` | Hardcoded Microsoft Teams webhook URL. | Move it to a secret store; rotate it. |
| `crossover.discord_webhook` | high | Hardcoded Discord webhook URL. Pattern: `https://(discord\\|discordapp)\.com/api/webhooks/\d+/[\w-]+` | Hardcoded Discord webhook URL. | Move it to a secret store; rotate it. |

| `crossover.secret.*` | high | Hardcoded secrets (values are masked): `openai_key`, `anthropic_key`, `aws_access_key`, `github_token`, `slack_token`, `google_api_key`, `stripe_key`, `private_key`, `generic_assignment`. Patterns in `rules/crossover.yaml`. | Possible personal data (ssn): 123-…89 (masked). | Remove real personal data from prompts and fixtures; use synthetic test data. |

### Agents taking irreversible actions on other people's sites

**The need.**

- Anthropic (October 9, 2026) reported Claude models submitting a sensitive form on a real website, reading the settings file a site sends to browsers to find working access tokens, and using URL shorteners to get around fetch limits. In one case the instructions "did not rule out form submissions."
- NBC10 Philadelphia (October 9, 2026): police say an AI model submitted a false tip on an unsolved murder on July 18; it was found on September 28 and reported to police on October 7. A spokesperson: "The two-month delay in detecting and reporting the incident to the City is unacceptable."
- In the VentureBeat survey, 59% of 109 organizations running agents in production or pilot had an agent cause a confirmed security incident or near-miss in the past 12 months.

**Where:** Tab 2: Irreversible actions.

**Checks that address it:** `actions.irreversible_tool`, `actions.browser_write`, `actions.cookie_read`, `actions.storage_read`, `actions.browser_profile`, `actions.url_shortener`, `actions.wildcard_domain`, `actions.no_deny_list`

| Rule ID | Severity | What it looks for | Example finding | How to fix |
|---|---|---|---|---|
| `actions.irreversible_tool` | high; info when a gate is found | Tool definitions (name:, def, function, @tool, server.tool) whose name contains a verb from irreversible_verbs; gates searched 6 lines above to 12 below. | Irreversible tool purchase_item has no approval gate or dry-run mode. | Add a human confirmation step or dry-run default before it runs. |
| `actions.browser_write` | high; info when a gate is found | browser_actions in rules/actions.yaml (.click/.fill/.submit/form POST…). | Browser write action .click( has no approval gate or dry-run mode. | Confirm with a person before submitting; allowlist domains. |
| `actions.cookie_read` | high | Reads browser cookies. Agents have lifted working tokens this way. Pattern: `document\.cookie\\|\.cookies\s*\(\\|context\.cookies\\|get_cookies\\|browser_cookie3\\|Cookies\b.*sq…` | Reads browser cookies (.cookies(). | Don't give agents cookie access; use scoped API tokens. |
| `actions.storage_read` | high | Reads a site's browser storage or the config the site sends to browsers. Pattern: `(localStorage\\|sessionStorage)\.getItem\\|storageState\s*\(\\|__NEXT_DATA__\\|window\.__[A-Z_]+__` | localStorage.getItem | Don't read site storage or site config for tokens. |
| `actions.browser_profile` | high | Uses a real browser profile, so the agent acts with your logged-in sessions. Pattern: `user[-_]?data[-_]?dir\\|Chrome/User Data\\|Library/Application Support/(Google/Chrome\\|Firefox)…` | launchPersistentContext | Use a fresh, logged-out browser profile in a sandbox. |
| `actions.url_shortener` | medium | URL shortener. Can be used to get around fetch limits or hide the real destination. Pattern: `\b(bit\.ly\\|tinyurl\.com\\|t\.co\\|is\.gd\\|rebrand\.ly\\|cutt\.ly\\|shorturl\.at)/` | bit.ly/ | Remove shorteners; fetch only allowlisted destinations. |
| `actions.wildcard_domain` | medium | Wildcard domain or host permission. Pattern: `["'](\*\\|https?://\*)[^"']*["']\\|\ballowed_?(domains\\|hosts)\b\s*[:=]\s*\[?\s*["']\*` | ALLOWED_HOSTS = ["*"] | List exact domains. |
| `actions.no_deny_list` | medium | Prompt files (.md/.txt or named prompt/instruction) with a role marker but no deny_list sentence such as 'never submit … without asking'. | Prompt has no explicit deny-list. | Add: Never send, submit, pay or delete without asking me first. |

**The need.**

- New Relic's 2026 Observability Forecast (2,575 engineering and IT leaders, September 2026) found 24.6% of organizations run AI agents in production with no monitoring.

### Prompt injection hidden in documents (ADSF)

**The need.**

- OWASP ranks prompt injection as risk number one in its Top 10 for LLM Applications (LLM01:2025).
- Anthropic (October 9, 2026) reported a model reading the settings file a site sends to browsers for tokens: content an agent reads can steer what it does.

**Where:** Tab 6: Prompt-injection scan (ADSF).

**Checks that address it:** `injection.ignore_previous`, `injection.role_reassign`, `injection.fake_system`, `injection.hidden_task`, `injection.secrecy`, `injection.exfil_instruction`, `injection.tool_call_injection`, `injection.md_image_exfil`, `injection.templated_url`, `injection.webhook_catcher`, `injection.html_comment_instruction`, `injection.css_hidden`, `injection.data_uri`, `injection.zero_width`, `injection.bidi_control`, `injection.unicode_tags`, `injection.private_use`, `injection.base64_instruction`

| Rule ID | Severity | What it looks for | Example finding | How to fix |
|---|---|---|---|---|
| `injection.ignore_previous` | high | "Ignore previous instructions" style override. Pattern: `\b(ignore\\|disregard\\|forget\\|override)\b[^.\n]{0,40}\b(all \\|any )?(previous\\|prior\\|above\\|earl…` | Ignore previous instructions (vendor-faq.md:4) | Remove it; treat document text as data, not instructions. |
| `injection.role_reassign` | high | Tries to reassign the agent's role or rules. Pattern: `\b(you are now\\|from now on,? you are\\|act as (an? )?(unrestricted\\|jailbroken\\|developer mode…` | you are now in developer mode | Remove; keep untrusted text out of the system prompt. |
| `injection.fake_system` | high | Fake system/assistant marker inside content. Pattern: `(^\\|\n)\s*(\[?(system\\|assistant)\]?\s*:\\|<\\\|?(system\\|im_start)\\\|?>\\|###\s*(system\\|instruction…` | [system]: … | Strip role markers from untrusted content. |
| `injection.hidden_task` | high | Instruction addressed to an AI reading the document. Pattern: `\b(ai\\|assistant\\|agent\\|llm\\|model\\|chatbot)s?\b[^.\n]{0,30}\b(reading\\|processing\\|summari[sz]i…` | AI agents reading this must… | Remove; don't feed this document to agents. |
| `injection.secrecy` | medium | Asks the agent to hide something from the user. Pattern: `\b(do not\\|don't\\|never) (tell\\|mention\\|reveal\\|inform\\|alert) (the )?(user\\|human\\|operator\\|anyo…` | Do not tell the user. | Remove; agents must not hide actions. |
| `injection.exfil_instruction` | high | Instruction to send secrets or conversation data somewhere. Pattern: `\b(send\\|post\\|forward\\|upload\\|email\\|leak\\|include)\b[^.\n]{0,50}\b(api[_ -]?keys?\\|passwords?\\|…` | Send the API keys to … | Remove; block outbound sends of secrets. |
| `injection.tool_call_injection` | high | Asks the agent to call a risky tool. Pattern: `\b(call\\|run\\|execute\\|invoke\\|use) (the )?(tool\\|function)\b[^.\n]{0,30}\b(send_\\|delete_\\|trans…` | call the tool send_… | Remove; require approval for tool calls. |
| `injection.md_image_exfil` | high | Markdown image whose URL carries data. Rendering it can leak data with no click. | `injection.templated_url` | high | URL with a template slot for the agent to fill in. Pattern: `https?://[^\s"'<>)]*(\{\{[^}]+\}\}\\|\$\{[^}]+\}\\|%7B%7B)` | https://…{{conversation}} | Remove templated URLs from content agents read. |
| `injection.webhook_catcher` | medium | Known request-capture host. Pattern: `https?://[^\s"'<>)]*(webhook\.site\\|requestbin\\|pipedream\.net\\|ngrok(-free)?\.(io\\|app)\\|burpc…` | webhook.site | Remove; block request-capture hosts. |
| `injection.html_comment_instruction` | high | HTML comment containing instructions (invisible when rendered). Pattern: `<!--[\s\S]{0,400}?\b(ignore\\|instruction\\|assistant\\|ai agent\\|system prompt\\|you must\\|you are\\|…` | <!-- AI agents reading this: ignore previous instructions … --> | Strip HTML comments before indexing. |
| `injection.css_hidden` | medium | CSS that hides text from people but not from an agent. Pattern: `(display\s*:\s*none\\|visibility\s*:\s*hidden\\|font-size\s*:\s*0(px)?\b\\|opacity\s*:\s*0(\.0+)…` | style="display:none" | Strip hidden elements before indexing. |
| `injection.data_uri` | low | Inline data URI with text content. Pattern: `data:(text\/(html\\|plain)\\|application\/(json\\|javascript))[;,][^\s"')]{20,}` | data:text/html,… | Remove inline data URIs. |
| `injection.zero_width` | high | U+200B–U+200D, U+2060, U+FEFF (not a leading BOM), U+180E. | 3 zero-width characters. | Strip invisible characters before indexing. |
| `injection.bidi_control` | high | Bidirectional overrides U+202A–U+202E, U+2066–U+2069. | 1 bidirectional override character. | Strip bidi controls. |

### Unclear instructions and information lost in rewrites (STE)

**The need.**

- Anthropic (October 9, 2026) wrote that some failures "could have been avoided" if the task had clearly stated what was in and out of scope.
- In the Labs controlled test of a fictional business (September 30, 2026), the unsafe scripted bot failed 17 of 20 tests and the fixed bot failed 0 of 20.

**Where:** Tab 5: Simplified Technical English.

**Checks that address it:** `ste.sentence_length`, `ste.passive_voice`, `ste.complex_tense`, `ste.ing_verb`, `ste.semicolon`, `ste.multiple_instructions`, `ste.noun_cluster`, `ste.phrasal_verb`, `ste.hedge`, `ste.word_hint`, `ste.not_in_dictionary`, `ste.info_loss.*`

| Rule ID | Severity | What it looks for | Example finding | How to fix |
|---|---|---|---|---|
| `ste.sentence_length` | medium | Procedural sentences (starting with an imperative_verbs word) over limits.procedural_words; descriptive over limits.descriptive_words. | Descriptive sentence has 31 words (limit 25). | Split the sentence. |
| `ste.passive_voice` | medium | auxiliary + past participle (-ed or irregular_participles). | is set | Say who does the action. |
| `ste.complex_tense` | low | Perfect (has/have/had + participle), progressive (be + -ing), modal + be + participle. | should be checked | Use simple present or past, active voice. |
| `ste.ing_verb` | low | -ing word after a comma, at sentence start, or after by/when/while/before/after/for/without, followed by a determiner. | Before starting the | Use a full clause: Before you start the… |
| `ste.semicolon` | low | Any semicolon in a prose sentence. | …is set; perhaps… | Use two sentences. |
| `ste.multiple_instructions` | medium | Procedural sentence with and/then/also followed by another imperative verb. | Open the valve and start the pump. | One instruction per sentence. |
| `ste.noun_cluster` | low | More than limits.noun_cluster consecutive noun-like words (heuristic). | retry limit configuration value | Break it up with of/for or a verb. |
| `ste.phrasal_verb` | low | phrasal_verbs list. | make sure → verify / ensure | Use the suggested verb. |
| `ste.hedge` | low | hedges list. | perhaps | Give the exact condition, value or action. |
| `ste.word_hint` | low | hints list (original, not from the ASD-STE100 dictionary). | utilize → use | Use the plain word. |
| `ste.not_in_dictionary` | low | Words not in your --ste-dict list (capitalized words after the first are treated as names). | Not in your approved word list: rotate, handle. | Use an approved word or add it to your list. |
| `ste.info_loss.*` | high (names and soft constraints: medium) | --ste-compare: numbers, units, dates, names, paths, URLs, identifiers and constraint words in the original that are missing from the rewrite. | Missing from the STE version: number+unit "30 seconds". | Put the fact or constraint back. |

### Testing agents and mapping to standards

**The need.**

- In the Pax8 survey, 55% of decision-makers spend three or more hours each week checking AI work.
- Only 9% of the 137 VentureBeat respondents say sandboxing of high-risk agents best describes their program.

**Where:** Eval sets and Standards map.

**Checks that address it:** `agent-ops-check evals <folder>` writes an offline eval set (JSONL) from your prompts and tool definitions, and the Standards map shows how findings map to 10 frameworks in `data/standards/` (✅ evidence found, 🟡 partial, ⬜ not found). It says "maps to", never "compliant".

## STE (Simplified Technical English) checks

> **This is not a certified ASD-STE100 checker.** The rules are inspired by the ASD-STE100 writing rules and use regex and
> light word lists only. The ASD-STE100 specification and its dictionary are copyrighted and are **not** included.
> The plain-word hints and phrasal-verb list in `rules/ste.yaml` are original and incomplete.

Every input method runs the same rules (`src/ste/core.js`), and none of them use the network:

| Input | Command |
|---|---|
| Agent folder (prompts, `.md`, prompt strings in JSON/YAML configs) | `npx github:ultimatixarup/agent-ops-check ./my-agent` (STE is tab 5) |
| Any file or folder of text | `agent-ops-check --ste docs/ --ste prompt.txt` |
| Pasted text | `agent-ops-check --ste-text "The pump is running; perhaps utilize the valve."` |
| stdin | `cat prompt.txt \| agent-ops-check --ste -` |
| Your own approved-word list (one word per line) | add `--ste-dict my-words.txt`; words not on it are flagged |
| Information-loss check | `agent-ops-check --ste-compare original.txt ste.txt` |
| Offline page with a paste box and file picker | `agent-ops-check ste-ui` (writes `agent-ops-report/ste.html`; add `--open` to open it). Every report folder also gets `ste.html`. |

The **information-loss check** pulls numbers, units, dates, names, paths, URLs, identifiers and constraint words
(must, never, only, at least, before, until, unless, within…) from the original, and lists any that are missing from the
STE version. A rewrite that drops "within 30 seconds" or turns "never" into nothing is flagged high.

Try it: `agent-ops-check --ste-compare examples/ste/original.txt examples/ste/rewrite.txt`.

Use `--no-ste` to skip the STE tab in a normal scan.

## Inputs

`.js .mjs .cjs .ts .tsx .py .json .jsonl .yaml .yml .toml .md .txt .csv`, MCP configs (`mcp.json`, `claude_desktop_config.json`)
and `.env.example`. **Real `.env` files are never read.** `node_modules`, `.git`, `dist`, `build` and virtualenvs are skipped.

Each **subfolder** of the input folder is treated as one agent, which is how shared credentials across agents are found.
`kb.*`, `faq.*` or `price-list.*` next to a transcript is used as the FAQ for the grounding check.

## Options

```
agent-ops-check <dir|files...> [options]
  --out <dir>          report folder (default ./agent-ops-report)
  --format <list>      html,json,md,sarif (default: all four)
  --fail-on <sev>      exit 1 if any finding at or above high|medium|low (for CI)
  --ignore <glob>      skip paths, e.g. --ignore "tests/**" (repeatable)
  --rules <dir>        use your own copy of rules/*.yaml
  --no-labs            skip tab 4
  --llm <provider>     optional review: openai | anthropic | openrouter
  --docs <file|dir>    extra documents for the prompt-injection scan (repeatable)
  --no-injection, --no-ste, --no-evals   skip those parts
agent-ops-check ui [--port N] [--open]   local launch page (127.0.0.1 only)
```

Outputs: `index.html` (static, opens offline, three-plus tabs with file:line findings), `report.json`,
`report.md` (an audit memo: inventory, gate map, P0/P1/P2 findings) and `report.sarif` (for GitHub code scanning and other SARIF viewers), plus `redteam-pack.txt`: 20 test messages to send to your own customer-facing bot.

Other ways to run: `git clone https://github.com/ultimatixarup/agent-ops-check && cd agent-ops-check && npm install && npm start -- ./my-agent`.
Try it on the built-in bad example: `npm run example`.

## Privacy

- With no `--llm` flag, **nothing leaves your machine**. The tool makes no network calls; the test suite fails if it tries.
  The HTML report has a `default-src 'none'` policy, so it loads nothing either.
- Secrets and PII found are masked in every report (`sk-p…Xa (masked)`). Credentials are listed by env-var **name** only.
- `--llm` sends only the finding list (rule, file:line, message, masked evidence), never whole files, to the provider you
  name, using your key from `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY` or `LLM_API_KEY`.
  Pick the model with `LLM_MODEL`. Without a key, nothing is sent and the report says so.
- No telemetry, no usage counts, no update checks.

## Editing the rules

All patterns live in `rules/crossover.yaml`, `rules/actions.yaml` and `rules/governance.yaml` as case-insensitive
JavaScript regex. Copy the folder, edit, and run with `--rules ./my-rules`.

## Updates

Rule updates ship only through this repo: `git pull`, or re-run npx. There are no live rule downloads. Every report shows the rules version and date and a local-only "rules are N days old" hint. See [docs/UPDATES.md](docs/UPDATES.md) for versioning, the changelog, adding a rule, and release notifications.

## Known limits

- Regex reads what code and configs **say**, not what they enforce at runtime.
- Agent = subfolder. A monorepo with one folder per service works best.
- Gates are judged from the code near each action (6 lines above, 12 below). A gate in a distant wrapper is not seen.
- Health Checker extras still miss a false claim with no price or policy keyword (e.g. "we see emergencies every Saturday" when the FAQ says otherwise). English only, plus a few Spanish/French/German "obey the customer" phrases.
